# Black&Milk

Персональный кофейный дневник: какие зёрна вы пьёте, как готовите кофе и сколько осталось в пачке.

## Состояние проекта

Работают двуязычная главная, аккаунты через Google и email/пароль, профиль, управление сессиями и админ-панель. Регистрация по умолчанию закрыта списком допуска email; администратор может открыть её всем. Реализованы подтверждение email, активация, восстановление пароля, блокировки, роли, удаления и журнал действий. Работает «Мой кофе»: зерно и молотый кофе в граммах, дрипы в штуках, смешанные наборы, приготовления, оценки, заметки и учёт остатков.

Публичная главная и сборка работают без секретов. Для аккаунтов нужны PostgreSQL и серверная конфигурация; Google требует OAuth-ключи, письма локально перехватывает Mailpit. Публичное размещение и внешняя доставка почты не выполнялись.

Первая полезная версия включает аккаунты, запасы кофе, смешанные наборы, приготовления, оценки 1–10, заметки и автоматический/ручной учёт остатков. Будущие Android/iOS-клиенты будут использовать общий REST API.

## Быстрый старт

Нужны Node.js **22.19+ в ветке 22** и pnpm **11.25.0** (версия закреплена в `package.json`). Если pnpm не установлен: `npm install --global pnpm@11.25.0`.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Откройте [русскую версию](http://localhost:3000/ru) или [английскую](http://localhost:3000/en). Корень `/` перенаправляет на `/ru`, независимо от языка браузера. Язык выбирается явно через адрес или переключатель.

Для работы аккаунтов выполните локальную настройку ниже. Без неё формы показывают понятное сообщение о недоступной конфигурации.

## Аккаунты локально

Нужен установленный и запущенный Docker с Linux-контейнерами:

```sh
pnpm setup:local
docker compose --env-file .env.local up -d
pnpm db:migrate
pnpm admin:bootstrap --email your-address@example.com
pnpm dev
```

`setup:local` создаёт `.env.local` со случайными секретами и не перезаписывает существующий файл. В команде администратора укажите свой настоящий email. Зарегистрируйтесь с этим адресом, откройте письмо в [локальном Mailpit](http://localhost:8025), подтвердите адрес и войдите. Роль администратора назначается только после подтверждения владения email. Если подтверждённый аккаунт уже есть, служебная команда назначает роль сразу; когда активный администратор уже существует, команда отказывается менять права.

Кабинет: `/ru/account`, безопасность: `/ru/account/security`, админка: `/ru/admin/users`. Для Google-входа добавьте ключи по [инструкции авторизации](docs/accounts.md). Mailpit не отправляет письма реальным адресатам. Секреты и `.local` не включаются в Git.

## Кофейный дневник

После обновления выполните `pnpm db:migrate` при настроенной базе, затем запустите приложение. Миграции не запускаются автоматически. Откройте `/ru/coffee` или `/en/coffee`; история — `/ru/brews` и `/en/brews`. Ссылки доступны в кабинете и шапке после входа.

Добавьте отдельную пачку/дрипы или набор с несколькими позициями. Для зерна и молотого кофе указывайте граммы, для дрипов — количество штук. «Выпил» записывает один дрип; затем можно добавить впечатление или отменить запись. Для зерна «Приготовить» открывает форму дозы. Правка/удаление приготовления пересчитывает остаток. «Уточнить остаток» сохраняет корректировку с причиной.

Есть поиск, фильтры, архив, даты годности, отметка «Хочу повторить» и «Купить снова». Набор может содержать разные форматы и обжарщиков. Его удаление сохраняет кофе и историю; архивирование набора архивирует компоненты. Подробнее — [предметная модель](docs/domain.md).

`pnpm test:coffee --workers=1` проверяет интерфейс на том же изолированном PostgreSQL-стенде, что и аккаунты. Сначала выполните production-сборку; снимки находятся в `test-results/coffee`. Не запускайте разные наборы тестов PostgreSQL одновременно: они используют общий тестовый порт или пересоздают схему явно заданной тестовой базы.

## Команды

Для разработки используется Webpack; причина выбора описана в архитектуре. Production-сборка использует стандартный Turbopack.

| Команда             | Назначение                                              |
| ------------------- | ------------------------------------------------------- |
| `pnpm dev`          | Локальная разработка                                    |
| `pnpm build`        | Production-сборка, включая standalone-вывод             |
| `pnpm start`        | Запуск production-сборки на порту 3000                  |
| `pnpm lint`         | ESLint                                                  |
| `pnpm format:check` | Проверка Prettier                                       |
| `pnpm format`       | Форматирование                                          |
| `pnpm typecheck`    | Генерация типов маршрутов и строгая проверка TypeScript |
| `pnpm test`         | Playwright: локали, навигация, мобильный экран и API    |

Перед первым запуском браузерных тестов установите Chromium: `pnpm exec playwright install chromium` (на Linux при необходимости `pnpm exec playwright install --with-deps chromium`). Тесты сами запускают production-сервер на `127.0.0.1:3100`, поэтому сначала выполните `pnpm build`. На машине должны быть свободны порт 3100 и ресурсы для Chromium.

Альтернатива загрузке Chromium — установленный Google Chrome: задайте `PLAYWRIGHT_CHANNEL=chrome` в окружении процесса тестов. В PowerShell: `$env:PLAYWRIGHT_CHANNEL = 'chrome'`, затем `pnpm test`. По умолчанию локальные проверки и CI используют Chromium от Playwright.

Полная проверка:

```sh
pnpm lint
pnpm format:check
pnpm typecheck
pnpm build
pnpm test
pnpm test:integration
pnpm test:accounts --workers=1
pnpm test:coffee --workers=1
git diff --check
```

## Структура

```text
src/
  app/          Страницы App Router и тонкие HTTP-обработчики
  assets/fonts/ Локальные шрифты и сохранённые исходные архивы
  components/   Компоненты интерфейса
  contracts/    Общие типы публичного API без серверных зависимостей
  i18n/         Правила маршрутизации и загрузки переводов
  server/       Серверная логика, отделённая от React и HTTP
messages/       Переводы ru/en
tests/          Сквозные проверки Playwright
docs/           Концепция, решения, модель данных, этапы и размещение
public/         Статические ресурсы, фотографии в images/coffee и OpenAPI
scripts/        Подготовка standalone-сборки со статическими ресурсами
```

Генерируемые файлы, локальные переменные окружения, отчёты тестов и `node_modules` исключены из Git. Зависимости и lockfile изменяются совместно.

`pnpm db:generate` создаёт миграции Drizzle, `pnpm db:migrate` применяет их. `drizzle/` хранится в Git. `pnpm test:integration` проверяет API на настоящем PostgreSQL; `pnpm test:accounts` запускает браузерные сценарии и сохраняет снимки кабинета и админки. Без `TEST_DATABASE_URL` тесты поднимают отдельный PostgreSQL 17 из dev-зависимости, без системных служб; данные удаляются при завершении. В CI используется отдельная база сервиса PostgreSQL. Не задавайте тестам рабочую базу: имя тестовой базы обязано оканчиваться на `_tests`, её публичная схема пересоздаётся.

## Оформление

Интерфейс следует визуальному коду Tasty Coffee: DIN Pro Condensed для заголовков, Gotham Pro для текста, светло-серый фон и кофейные фотокарточки. Шрифты и фотографии подключаются локально, внешние запросы для сборки не нужны. Предоставленные исходники сохранены; подключены только используемые начертания. Правила для обеих локалей и следующих страниц описаны в [дизайн-системе](docs/design-system.md).
