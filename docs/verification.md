# Проверка инициализации

Дата: 10 ноября 2026 года. Окружение: Windows, Node.js 22.19.0, pnpm 11.25.0. Проверена локальная production-сборка; облачное размещение не выполнялось.

## Пройдено

- Чистая установка: папка `node_modules` удалена и пересоздана по неизменённому lockfile с `--frozen-lockfile --offline`. Все необходимые пакеты взяты из предварительно наполненного кеша.
- `pnpm lint`, `pnpm format:check`, `pnpm typecheck` и `pnpm build` прошли.
- `pnpm peers check`: несовместимых peer-зависимостей нет.
- `pnpm test --workers=2`: **12 проверок прошли** на production standalone-сервере, desktop и эмуляции Pixel 7. Локально использован установленный Google Chrome через `PLAYWRIGHT_CHANNEL=chrome`.
- Проверены ru/en, язык HTML и заголовка, переключение локалей, отсутствие горизонтального переполнения, переход к описанию дневника, редирект `/` → `/ru` при английском языке браузера, 404, health JSON и доступность OpenAPI без локализующего редиректа.
- `pnpm start` запускает standalone-сервер. Статические файлы и значок сайта доступны; для запуска не потребовались база или Google-ключи.
- Страницы осмотрены на снимках: ru/en при ширине 1440 px, ru при ширине 393 px. При итоговом просмотре нет ошибок JavaScript, ошибок консоли или неудачных сетевых запросов.
- `pnpm dev` проверен с выбранным Webpack: первые одновременные запросы `/ru`, `/en` и `/api/v1/health` после очистки кеша вернули 200. Автоматические изменения `AGENTS.md` отключены.

## Особенности локальной установки

Ограниченный Windows-процесс не позволял pnpm создавать ссылки в общем хранилище. Для локальной проверки использованы `--store-dir .pnpm-store --config.node-linker=hoisted --config.package-import-method=copy`. Хранилище исключено из Git и Docker-контекста. Эти параметры не закреплены как обязательные для обычной установки или CI.

Запуски pnpm выполнялись явно через Node.js 22, поскольку предоставленная окружением команда-обёртка pnpm использует собственный Node.js 24. Сборка запускалась с доступом к пользовательскому кешу нативного компилятора. Это особенности среды проверки; проект не требует смены runtime на Node.js 24.

Во время разработки исправлены отсутствие контекста у первоначального переключателя языка, обработка относительного `Location` в тесте и отсутствующий значок вкладки. Для режима разработки выбран Webpack после воспроизведения сбоя холодных параллельных запросов с Turbopack; подробности решения — в архитектуре. Итоговая production-версия повторно прошла весь набор тестов.

## Не проверено

- **Сборка и запуск Docker-образа:** Docker CLI/движок на машине отсутствуют. Dockerfile и отдельная проверка контейнера в GitHub Actions подготовлены, но успешный запуск контейнера пока не подтверждён.
- **GitHub Actions:** workflow создан, но не запускался, поскольку репозиторий не отправлялся на удалённый сервер.
- **Vercel и публичный сервер:** размещение не выполнялось; инструкции подготовлены.
- **База, Google OAuth и кофейные сценарии:** не реализованы на этом этапе и не имитировались в проверках.

Перед следующим этапом достаточно повторять штатные команды из README; отдельно подтвердить Docker там, где он установлен.

## Редизайн по Tasty Coffee — 10 ноября 2026 года

Проверены обновлённые `/ru` и `/en`. Новые сервисы, API и обязательные переменные окружения не добавлялись.

- Предоставленные 92 файла шрифтов и 4 JPG перенесены в постоянные каталоги. SHA-256 каждого файла до и после переноса совпал; исходники сохранены полностью.
- Внутренние имена и кириллица проверены fontTools по исходным TTF: DIN Pro Condensed Regular / Medium / Black и Gotham Pro Regular / Medium. В браузере загружены пять используемых начертаний, синтетические начертания отключены.
- Установка `pnpm install --frozen-lockfile --offline` завершилась без изменения зависимостей и lockfile. Node.js 22.19.0, pnpm 11.25.0; `pnpm exec node --version` также подтвердил ветку 22.
- `pnpm lint`, `pnpm format:check`, `pnpm typecheck`, `pnpm build` и `git diff --check` прошли. Для typecheck и сборки понадобился доступ к пользовательскому кешу SWC, как и при инициализации.
- `PLAYWRIGHT_CHANNEL=chrome pnpm test --workers=2`: **18 проверок прошли**, 2 пропущены намеренно: матрица размеров выполняется один раз для каждой локали в desktop-проекте, а не дублируется в mobile-проекте.
- Сохранены действующие проверки переводов, языка HTML, заголовка, RU/EN, основного якоря, перенаправления `/`, 404, health API и OpenAPI. Добавлены клавиатурный skip-link, фокус фотокарточек и переходы к каждому описанию.
- Обе локали проверены на ширинах 360, 390, 768, 1280 и 1440 px. Проверены раскладка карточек, загрузка и декодирование всех пяти изображений, отсутствие горизонтального переполнения, внешних запросов, ошибок JavaScript, ошибок консоли и HTTP-ошибок ресурсов.
- Созданы и визуально осмотрены 10 полностраничных снимков и 2 настольных превью. При просмотре проверены переносы, читаемость подписей, кадрирование, интервалы и мобильная композиция. Снимки находятся в `test-results` в каталогах тестов `local fonts and photographs render across responsive widths`; имена — `{locale}-{width}.png` и `{locale}-preview.png`. Это генерируемые артефакты, в Git не включены.
- Во время проверки уточнён тест ресурсов: `net::ERR_ABORTED` у устаревшего кандидата `srcset` при смене ширины не считается сетевым сбоем. Реальная загрузка и декодирование замещающего изображения проверяются отдельно; перед снимком ожидается его отрисовка.
- Компоненты остаются серверными, изображения используют Next Image с `sizes`, приоритет загрузки задан первой фотокатегории. Проверка по React Best Practices не потребовала новых клиентских зависимостей.

Docker, GitHub Actions, облачный деплой и будущие аккаунты/кофейные операции в рамках редизайна не проверялись. Ограничения инициализации выше продолжают действовать.

## Аккаунты, кабинет и админ-панель — 10 ноября 2026 года

Текущий этап реализован поверх редизайна Tasty Coffee. Предыдущие разделы выше описывают исторические ограничения каркаса; аккаунты теперь реализованы и проверены отдельно. Изменения оставлены без коммитов.

- Node.js 22.19.0, pnpm 11.25.0. Окончательная установка с --frozen-lockfile --offline прошла без разрешения новых версий. Для ограниченного Windows-процесса сохранены локальное хранилище .pnpm-store, hoisted-размещение и копирование файлов; это параметры проверки, не обязательная конфигурация проекта.
- Подключены Better Auth 1.7.19, Drizzle и pg. Две миграции применены к чистой настоящей PostgreSQL 17: таблицы, индексы, ограничения ролей/режима регистрации и первоначальный invite-only.
- Интеграционные проверки: **13 прошли** (12 сценариев и родительский тест). Проверены прямые HTTP-запросы, закрытая/открытая регистрация, подтверждение адреса, bootstrap, изоляция, запрет повышения прав через Better Auth, сессии, блокировки, конкурентная одноразовая активация, истечение/перевыпуск токенов, сброс пароля, OAuth, явная привязка провайдера, конкурентные административные изменения, удаление и ограничение входов.
- OAuth использовал отдельный локальный провайдер. Дополнительный процесс с NODE_ENV=production подтвердил, что тестовый провайдер не регистрируется. Сообщения account_not_linked и Invalid password в негативных тестах ожидаемы: они подтверждают отказ в доступе.
- Браузерные проверки аккаунтов: **10 прошли** в установленном Google Chrome, desktop и эмуляции Pixel 7. Проверены профиль, сессии, выход, сохранение раздела при ru/en, выдача допуска, регистрация и подтверждение письмом, создание/активация/блокировка/удаление пользователя, восстановление и изменение пароля.
- Адаптивная матрица: 13 страниц × 2 локали × 5 ширин (360, 390, 768, 1280, 1440), плюс отдельный мобильный снимок админки. **131 снимок** сохраняется в test-results/accounts. Проверено отсутствие горизонтального переполнения. Выборочно визуально осмотрены профиль, настольная и мобильная админка, мобильная форма входа. Диалог проверен с Tab, Escape и возвратом фокуса.
- Проверки публичного сайта: **18 прошли, 2 намеренно пропущены**, как в исходном редизайне: мобильный проект не дублирует полную матрицу размеров. Работают фотографии, локальные шрифты, якоря, клавиатура, локали, 404, health и расширенный OpenAPI. Артефакты теперь разделены на test-results/scaffold и test-results/accounts.
- Линтер без предупреждений, форматирование, строгая проверка TypeScript и production-сборка прошли. Сборка не требует подключения к базе или Google-ключей. Рабочие исходники шрифтов и фотографий не изменялись.
- В браузерных тестах использован отдельный локальный SMTP-перехватчик, в интеграционных — транспорт в памяти. Письма реальным адресатам не отправлялись. Счётчики лимитов очищаются между независимыми браузерными сценариями только тестовой фикстурой; production-лимиты не отключались.

Ограничения: Docker CLI/движок отсутствуют, поэтому Compose и сборка Docker-образа здесь не запускались. Для тестов поднят настоящий PostgreSQL из dev-зависимости, без системных служб или новых пользователей ОС. CI с PostgreSQL и контейнерными проверками подготовлен, но не запускался на удалённом сервере. Реальный Google OAuth не проверен: нужны собственные ключи и разрешённый redirect URI. Внешняя почта и публикация не выполнялись.

Для живого использования аккаунтов выполните настройку из accounts.md: Docker, pnpm setup:local, миграции и bootstrap с вашим email. Локальный публичный сервер на порту 3000 возвращён после пересборки; без runtime-конфигурации формы честно сообщают о необходимости настройки.
