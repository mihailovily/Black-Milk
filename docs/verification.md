# Проверка инициализации

Дата: 10 ноября 2026 года. Окружение: Windows, Node.js 22.19.0, pnpm 11.25.0. Проверена локальная production-сборка; облачное размещение не выполнялось.

## Пройдено

- Чистая установка: папка `node_modules` удалена и пересоздана по неизменённому lockfile с `--frozen-lockfile --offline`. Все необходимые пакеты взяты из предварительно наполненного кеша.
- `pnpm lint`, `pnpm format:check`, `pnpm typecheck` и `pnpm build` прошли.
- `pnpm peers check`: несовместимых peer-зависимостей нет.
- `pnpm test --workers=2`: **12 проверок прошли** на production standalone-сервере, desktop и эмуляции Pixel 7. Локально использован установленный Google Chrome через `PLAYWRIGHT_CHANNEL=chrome`.
- Проверены ru/en, язык HTML и заголовка, переключение локалей, отсутствие горизонтального переполнения, переход к описанию дневника, редирект `/` → `/ru` при английском языке браузера, 404, health JSON и доступность OpenAPI без локализующего редиректа.
- `pnpm start` запускает standalone-сервер. Статические файлы и значок сайта доступны; для запуска не потребовались база или Google-ключи.
- Страницы осмотрены на снимках: ru/en при ширине 1440 px, ru при ширине 393 px. При итоговом просмотре нет ошибок JavaScript, ошибок консоли или неудачных сетевых запросов.
- `pnpm dev` проверен с выбранным Webpack: первые одновременные запросы `/ru`, `/en` и `/api/v1/health` после очистки кеша вернули 200. Автоматические изменения `AGENTS.md` отключены.

## Особенности локальной установки

Ограниченный Windows-процесс не позволял pnpm создавать ссылки в общем хранилище. Для локальной проверки использованы `--store-dir .pnpm-store --config.node-linker=hoisted --config.package-import-method=copy`. Хранилище исключено из Git и Docker-контекста. Эти параметры не закреплены как обязательные для обычной установки или CI.

Запуски pnpm выполнялись явно через Node.js 22, поскольку предоставленная окружением команда-обёртка pnpm использует собственный Node.js 24. Сборка запускалась с доступом к пользовательскому кешу нативного компилятора. Это особенности среды проверки; проект не требует смены runtime на Node.js 24.

Во время разработки исправлены отсутствие контекста у первоначального переключателя языка, обработка относительного `Location` в тесте и отсутствующий значок вкладки. Для режима разработки выбран Webpack после воспроизведения сбоя холодных параллельных запросов с Turbopack; подробности решения — в архитектуре. Итоговая production-версия повторно прошла весь набор тестов.

## Не проверено

- **Сборка и запуск Docker-образа:** Docker CLI/движок на машине отсутствуют. Dockerfile и отдельная проверка контейнера в GitHub Actions подготовлены, но успешный запуск контейнера пока не подтверждён.
- **GitHub Actions:** workflow создан, но не запускался, поскольку репозиторий не отправлялся на удалённый сервер.
- **Vercel и публичный сервер:** размещение не выполнялось; инструкции подготовлены.
- **База, Google OAuth и кофейные сценарии:** не реализованы на этом этапе и не имитировались в проверках.

Перед следующим этапом достаточно повторять штатные команды из README; отдельно подтвердить Docker там, где он установлен.
