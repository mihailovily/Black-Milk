# Этапы разработки

Документ отделяет текущий каркас от будущих возможностей. Галочки обозначают реализованный объём; результаты конкретных проверок фиксируются отдельно.

## 1. Инициализация — текущий этап

- [x] Согласовать назначение, стек, границы первой версии и правила остатков.
- [x] Описать архитектуру, предметную модель и порядок развития.
- [x] Создать запускаемый Next.js-каркас на русском и английском.
- [x] Добавить health API, OpenAPI, инструменты качества и Playwright.
- [x] Подготовить Dockerfile, инструкции Vercel и локального запуска.
- [x] Зафиксировать разрешение на локальные коммиты.

Готовность: установка по lockfile, lint, форматирование, типы, сборка и сквозные проверки проходят без базы и OAuth. Сборка и запуск Docker проверяются при наличии Docker; отсутствие инструмента явно указывается в отчёте, а не считается успешной проверкой.

## 2. База и Google-вход

Подключить PostgreSQL, Drizzle и Better Auth; добавить схему, миграции и безопасную конфигурацию Google OAuth. Реализовать вход, выход, защищённые страницы и авторизацию API. На своём сервере и Vercel использовать одинаковую предметную схему.

Готовность: вход создаёт/восстанавливает аккаунт, выход завершает сессию, анонимный клиент не получает личные данные; тесты подтверждают изоляцию пользователей. Ошибки настроек явно диагностируются. Публиковать приложение без работающей авторизации нельзя.

## 3. Пачки

Создание, редактирование, список, просмотр и архивирование личных пачек; исходная масса и описание кофе. Веб работает через документированный API. Есть обработка ошибок и пустых состояний.

Готовность: данные сохраняются между сессиями и доступны на втором устройстве; пользователь не видит чужие пачки.

## 4. Приготовления и остатки

Записи приготовления, способы, оценки 1–10 и заметки. Автоматическое списание и возврат расхода при правке/удалении, ручные корректировки. Транзакции и контроль конкурентных изменений.

Готовность: выполнены сценарии из предметной модели, включая параллельные списания и откат неудачных операций. Первый полезный продукт готов после завершения этого этапа.

## 5. Подготовка к публичному запуску

Проверить мобильную доступность, клавиатурную навигацию, локализацию, защиту авторизации и API. Добавить обработку повторных запросов записи, ограничение злоупотреблений, резервное копирование и восстановление базы, наблюдаемость без утечки личных данных, удаление аккаунта. Проверить реальное размещение и настроить production OAuth.

Готовность: сквозной сценарий с реальным аккаунтом пройден в целевом окружении, восстановление данных проверено, ограничения и порядок эксплуатации документированы.

## 6. Мобильные клиенты

Разработать Android/iOS-клиенты, подключить их к существующему API и проверить мобильную авторизацию. Выбор Expo/React Native или другой реализации сделать отдельным решением на этом этапе; общий UI с вебом не является требованием. PWA и офлайн-синхронизация требуют отдельного согласования.
